# 心理健康智能医疗助手 v1.0.0：API 与数据结构

状态：冻结契约
版本：1.0.0
基础路径：`/api/v1`
日期：2026-08-06

## 1. 通用协议

- 传输：开发环境 HTTP；生产环境只允许 HTTPS。
- 编码：UTF-8 JSON；SSE 为 `text/event-stream`。
- 命名：请求、响应和事件字段统一 `snake_case`。
- 时间：UTC RFC 3339，例如 `2026-08-06T08:30:00.000Z`；仅业务日期使用 `YYYY-MM-DD`。
- ID：服务端生成的不可猜测字符串，最大 64 字符；不得使用账号、身份证或手机号作为主键。
- 认证：服务端 opaque session Cookie；不在 JavaScript、URL 或普通响应中暴露 session token。
- 写请求：除登录、注册外，必须带 `X-CSRF-Token`；前端从当前会话接口取得 token。
- 幂等：创建预约、医生审批、决定、夜班和 Agent run 接受 `Idempotency-Key`，1～128 个可打印 ASCII 字符。
- 分页：`limit` 默认 50、最大 100；`offset` 默认 0。v1 使用稳定排序加 offset。

### 1.1 统一成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "request_id": "req_01J..."
}
```

### 1.2 统一错误响应

```json
{
  "code": 40101,
  "message": "登录状态无效或已过期",
  "data": {
    "error": "AUTH_REQUIRED"
  },
  "request_id": "req_01J..."
}
```

客户端只依赖 HTTP 状态、数字 `code`、稳定 `data.error` 和字段错误；`message` 可本地化。生产响应不含 SQL、堆栈、密钥、文件绝对路径或供应商原始报错。

### 1.3 错误码

| HTTP | code | error | 含义 |
|---:|---:|---|---|
| 400 | 40001 | `VALIDATION_ERROR` | 字段、枚举、日期或状态不合法 |
| 400 | 40002 | `INVALID_STATE_TRANSITION` | 当前状态不允许该动作 |
| 401 | 40101 | `AUTH_REQUIRED` | 未登录、会话过期或已撤销 |
| 401 | 40102 | `INVALID_CREDENTIALS` | 角色、标识符或密码不匹配 |
| 423 | 42301 | `LOGIN_TEMPORARILY_LOCKED` | 8 次失败后临时锁定 |
| 403 | 40301 | `PERMISSION_DENIED` | 角色不允许 |
| 403 | 40302 | `DATA_SCOPE_DENIED` | 访问超出本人/分配范围 |
| 403 | 40303 | `CSRF_FAILED` | CSRF 缺失或不匹配 |
| 403 | 40304 | `ORIGIN_DENIED` | 请求 Origin 不属于同源或显式允许源 |
| 404 | 40401 | `RESOURCE_NOT_FOUND` | 资源不存在或不可见 |
| 409 | 40901 | `CONFLICT` | 唯一标识、重复预约、夜班冲突 |
| 409 | 40902 | `IDEMPOTENCY_CONFLICT` | 同一幂等键请求体不同 |
| 422 | 42201 | `APPOINTMENT_NOT_ELIGIBLE` | 不满足指定医生资格等规则 |
| 413 | 41301 | `REQUEST_BODY_TOO_LARGE` | 声明或实际请求体超过硬上限 |
| 429 | 42901 | `RATE_LIMITED` | 请求频率超限 |
| 503 | 50301 | `DATABASE_UNAVAILABLE` | E 盘/挂载库缺失、只读或不可连接 |
| 503 | 50302 | `MODEL_UNAVAILABLE` | DeepSeek 超时、限流或不可用且无文本降级 |
| 503 | 50303 | `DEPENDENCY_NOT_READY` | 就绪依赖未满足 |
| 500 | 50001 | `INTERNAL_ERROR` | 已记录 request_id 的受控内部错误 |

登录第 7 次失败仍使用 HTTP 401/`INVALID_CREDENTIALS`，`data.warning = "ONE_ATTEMPT_REMAINING"`；第 8 次使用 HTTP 423 并返回 `locked_remaining_seconds`。

## 2. 认证与注册

### `POST /auth/login`

无需 Cookie/CSRF。请求：

```json
{
  "identity_type": "patient",
  "account": "P001 or phone or email",
  "password": "string"
}
```

约束：`identity_type ∈ patient|doctor|assistant|admin`；`account` 1～100；`password` 1～1024。`admin` 身份类型允许普通管理员和最高管理员。

成功 `data`：

```json
{
  "role": "patient",
  "display_name": "测试患者001",
  "redirect_path": "/patient/index.html",
  "expires_at": "2026-08-06T10:00:00.000Z",
  "must_change_password": true,
  "csrf_token": "opaque"
}
```

服务端同时设置 `mh_session` Cookie：`HttpOnly; SameSite=Lax; Path=/; Secure`（本地 HTTP 可配置关闭 Secure）。

失败 `data` 可含：`remaining_attempts`、`warning`、`locked_remaining_seconds`，不返回“账号存在/不存在”。

### `POST /auth/logout`

需要 Cookie + CSRF。撤销当前会话并清 Cookie。重复调用成功。

### `GET /auth/session`

需要 Cookie。返回：

```json
{
  "user_id": "usr_...",
  "account": "P001",
  "role": "patient",
  "display_name": "测试患者001",
  "expires_at": "2026-08-06T10:00:00.000Z",
  "must_change_password": false,
  "csrf_token": "opaque"
}
```

### `POST /registrations`

无需 Cookie/CSRF。请求：

```json
{
  "role": "patient",
  "password": "string",
  "display_name": "string",
  "id_card": "string",
  "phone": "string",
  "email": "string",
  "department": null,
  "professional_title": null
}
```

患者成功：`account`、`status = active`。医生成功：`registration_request_id`、`status = pending_approval`，`account = null`；部门必填。

身份证、手机号和邮箱只在 TLS 请求内出现；数据库保存查重 fingerprint 与脱敏显示值，日志不记录原文。

### `GET /admin/doctor-registrations`

管理员/最高管理员；查询 `status=pending|approved|rejected`、`limit`、`offset`。返回申请最小字段，不返回身份证、手机号、邮箱原文或密码。

### `POST /admin/doctor-registrations/{registration_request_id}/decision`

管理员/最高管理员，需 CSRF + `Idempotency-Key`：

```json
{
  "action": "approve",
  "review_note": "string or null"
}
```

`action ∈ approve|reject`。批准返回生成的 `D###`；重复幂等请求返回首次结果。

## 3. 管理目录

### `GET /admin/directory/{target_role}`

`target_role ∈ patient|doctor|assistant|admin`。查询参数：`keyword`、`account_status`、`blacklisted`、`employment_status`、`limit`、`offset`。

- 管理员仅可查 `patient|doctor|assistant`。
- 最高管理员额外可查 `admin`。
- `employment_status` 仅用于医生/助理。

返回：

```json
{
  "items": [
    {
      "user_id": "usr_...",
      "account": "D001",
      "display_name": "测试医生001",
      "role": "doctor",
      "account_status": "active",
      "blacklisted": false,
      "employment_status": "active",
      "department": "心理科",
      "professional_title": "医师",
      "created_at": "2026-08-06T00:00:00.000Z",
      "last_login_at": null
    }
  ],
  "total": 5,
  "limit": 50,
  "offset": 0
}
```

不适用字段为 `null`，不因角色返回隐藏字段的空壳。

## 4. 患者页面助手

枚举：

- `page`: `overview|support|assessments|wellbeing|resources|care`
- `event`: `page_open|feature_open|message`
- `response_type`: `page_intro|page_answer|out_of_scope|care_navigation|crisis_support|introduction_suppressed`

### `POST /patient/page-assistant/respond`

仅患者，需 CSRF：

```json
{
  "page": "overview",
  "message": "",
  "assistant_session_id": null,
  "feature_key": "page",
  "event": "page_open"
}
```

`message` 最大 2000；`feature_key` 1～64。打开事件不能携带 message，message 事件必须携带 message。

返回：

```json
{
  "response_type": "page_intro",
  "page": "overview",
  "answer": "...",
  "age_group": "adult",
  "suggested_page": null,
  "doctors": [],
  "requires_guardian_support": false,
  "crisis_contacts": [],
  "assistant_session_id": "pas_...",
  "feature_key": "page",
  "usage_count": 1,
  "introduction_suppressed": false,
  "degraded": false
}
```

`doctors[]` 字段：`doctor_user_id`、`display_name`、`department`、`professional_title`、`availability`、`availability_label`、`appointment_count`、`patient_queue_position`、`is_previous_doctor`、`last_visit_at`、`expected_available_at`、`leave_remaining_days`。

### `GET /patient/page-assistant/sessions/{assistant_session_id}/messages`

仅会话所属患者。返回 `assistant_session_id` 及按时间升序的 `role`、`content`、`page`、`feature_key`、`created_at`。

### `GET /patient/page-assistant/usage`

查询 `page` 和可选 `feature_key`，返回 `usage_count`、`introduction_count`、`introduction_suppressed`。

## 5. 预约与排班

### `PUT /doctors/me/capacities/{appointment_date}`

仅医生本人，目标日期必须是服务端本地业务日期之后第 1 或第 2 天：

```json
{ "capacity": 12, "expected_version": 2 }
```

容量 0～1000；`expected_version` 可选，用于并发更新。返回医生、日期、容量、当前计数和新版本。

### `GET /doctors/{doctor_user_id}/appointment-summary`

已登录角色；查询 `appointment_date`。患者只得到公开状态、容量是否设置、预约人数和是否可选，不得到患者名单。

### `POST /patient/appointments`

仅患者，需 CSRF + 幂等键：

```json
{
  "doctor_user_id": "usr_doctor",
  "appointment_date": "2026-08-08"
}
```

返回：`appointment_id`、服务端 patient/doctor ID、日期、状态、`completed_visit_count`、容量、预约人数、队列位置和 message。

### `POST /patient/appointments/{appointment_id}/decision`

仅预约所属患者，需幂等键：

```json
{ "decision": "continue_request" }
```

`decision ∈ switch_doctor|continue_request`，仅允许从 `awaiting_patient_decision` 转移。

### `GET /doctors/me/appointments/pending-decisions`

仅医生，返回分配给本人的 `awaiting_doctor_decision` 预约最小患者字段。

### `POST /doctors/me/appointments/{appointment_id}/decision`

仅对应医生，需幂等键：

```json
{
  "decision": "decline",
  "communication_mode": "gentle"
}
```

`decision ∈ accept|decline`；拒绝时 `communication_mode ∈ direct|gentle` 必填，接受时必须为 null。

### `GET /assistants/me/coordination-queue`

仅助理，返回等待患者/医生决定和最近拒绝结果的最小协调字段，不返回病历正文。

### `GET /night-shifts/{shift_date}`

已登录角色；返回日期、医生 ID、医生显示名。普通患者不返回 `assigned_by_user_id`。

### `PUT /night-shifts/{shift_date}`

管理员/最高管理员，需 CSRF + 幂等键：

```json
{ "doctor_user_id": "usr_doctor" }
```

目标医生须在职且账号可用；每日期只有一个记录。替换既有值必须明确传 `replace = true` 并审计旧值。

### 预约状态机

```text
create -> queued
       -> awaiting_patient_decision
awaiting_patient_decision -> change_requested
                          -> awaiting_doctor_decision
awaiting_doctor_decision -> queued_over_capacity
                         -> declined_direct
                         -> declined_gentle
queued|queued_over_capacity -> completed|cancelled
```

不存在的转换统一返回 `INVALID_STATE_TRANSITION`。

## 6. 医生/助理工作助手与只读工具

### `POST /{role}/work-assistant/respond`

`role` 仅允许 `doctor|assistant` 且必须与会话角色一致：

```json
{
  "page": "schedule",
  "feature_key": "daily_queue",
  "message": "帮我查明天的安排",
  "assistant_session_id": null
}
```

返回：`response_type`、`answer`、`assistant_session_id`、`tool_calls[]`、`degraded`。每个 `tool_calls[]` 只返回 `tool_call_id`、`tool_name`、`status`、`result_summary`、`latency_ms`，不回传模型的隐藏推理或敏感参数。

v1 注册工具：

| 工具 | 医生 | 助理 | 数据范围 |
|---|:---:|:---:|---|
| `get_my_schedule` | 是 | 否 | 医生本人 |
| `get_my_appointment_queue` | 是 | 否 | 医生本人队列 |
| `get_visible_patient_summary` | 是 | 是 | 已分配/协调最小字段 |
| `get_doctor_schedule` | 否 | 是 | 医生公开工作/休假与容量摘要 |
| `get_coordination_queue` | 否 | 是 | 助理协调队列 |
| `get_night_shift` | 是 | 是 | 指定日期 |
| `search_medicine_inventory` | 是 | 是 | 库存只读字段 |

## 7. Agent 运行、异步任务与 SSE

### 创建任务

- `POST /patient/page-assistant/tasks`
- `POST /{role}/work-assistant/tasks`，其中 `role=doctor|assistant`

请求体分别复用对应同步助手接口。服务端只从 Cookie 会话注入 `user_id/role`。患者危机规则在创建任务前同步执行；命中时返回 HTTP 200、`mode=synchronous` 和危机支持响应，不创建任务、不调用模型。其他请求进入队列并返回 HTTP 202：

```json
{
  "mode": "asynchronous",
  "task_id": "task_...",
  "status": "QUEUED",
  "stream_url": "/api/v1/agent-tasks/task_.../events",
  "cancel_url": "/api/v1/agent-tasks/task_.../cancel"
}
```

### `GET /agent-tasks/{task_id}`

仅任务创建者可访问；返回 `status`、安全最终输出、稳定错误码和开始/结束时间。其他用户统一得到任务不存在，避免枚举任务 ID。

### `GET /agent-tasks/{task_id}/events`

SSE 支持 `Last-Event-ID`。每个事件：

```text
id: 3
event: message.delta
data: {"event_id":3,"task_id":"task_...","text":"增量文本","created_at":"..."}
```

标准事件：

- `task.created`
- `task.started`
- `message.delta`
- `task.waiting`
- `task.completed`
- `task.failed`
- `task.cancelled`
- `heartbeat`

事件 ID 是任务内从 1 开始的单调整数。客户端使用 `Last-Event-ID` 或 `after` 重连，服务端从下一事件补发。`task.completed` 必含完整最终响应；`task.failed` 必含稳定错误码；部分增量、客户端断流或模型流异常均不得把任务标记成功。

### `POST /agent-tasks/{task_id}/cancel`

仅创建者；已终态调用幂等成功并返回当前状态。

### 任务状态

`PENDING|QUEUED|RUNNING|WAITING_FOR_USER|SUCCEEDED|FAILED|CANCELLED`。终态为后三者中的 `SUCCEEDED|FAILED|CANCELLED`。

## 8. 运行接口

### `GET /health/live`

只检查进程事件循环，始终不查询模型。存活返回 HTTP 200。

### `GET /health/ready`

检查配置、数据库路径存在/可连接、schema 版本和只读查询；不强制调用 DeepSeek。未就绪返回 503 及脱敏依赖状态。

### `GET /metrics`

默认仅内网或管理员可见。不得含账号、姓名、会话消息、证件、手机号、邮箱或 API Key 标签。

## 9. v9 数据结构目标

在阶段 5 形成 migration；此处冻结逻辑字段。

### `user_sessions` 增量

- `csrf_token_hash TEXT NOT NULL`
- `ip_fingerprint TEXT NULL`
- `user_agent_hash TEXT NULL`

### `idempotency_records`

- `id`, `user_id`, `scope`, `idempotency_key_hash`, `request_hash`
- `response_status`, `response_json`, `expires_at`, `created_at`
- 唯一：`(user_id, scope, idempotency_key_hash)`

### `api_rate_limits`

- `bucket_key`, `window_started_at`, `request_count`, `blocked_until`, `updated_at`
- key 必须为 pepper 后 fingerprint，不保存原 IP、账号或 token。

### `async_tasks` / `async_task_events`

- 任务：所有者、角色、任务类型、状态、最小输入/最终输出、取消标记、超时及时间戳。
- 事件：任务内单调序号、SSE 事件类型、最小数据和创建时间。
- 任务和事件始终按 `owner_user_id` 做数据范围检查。

### `audit_events` v9 增量

- 新增 `request_id`、`ip_fingerprint`、`resource_fingerprint`、`metadata_json`。
- IP、账号标识和资源 ID 只保存 pepper/HMAC 指纹；元数据使用允许字段集合。
- `BEFORE UPDATE/DELETE` 触发器强制追加式审计，任何修改或删除都会失败。

### `agent_runs`

- `id`, `user_id`, `agent_type`, `assistant_session_id`, `status`, `current_node`
- `input_json`（脱敏/最小化）、`output_json`, `error_code`, `model_name`, `prompt_version`
- `input_tokens`, `output_tokens`, `started_at`, `finished_at`, `created_at`, `updated_at`

### `agent_run_events`

- `id`, `run_id`, `sequence`, `event_type`, `data_json`, `created_at`
- 唯一：`(run_id, sequence)`

### `tool_calls`

- `id`, `agent_run_id`, `tool_name`, `arguments_json`（脱敏）、`result_summary_json`
- `status`, `latency_ms`, `error_code`, `created_at`, `finished_at`

### `work_assistant_sessions` / `work_assistant_messages`

- session：`id`, `owner_user_id`, `role`, `last_page`, `status`, timestamps
- message：`id`, `session_id`, `role`, `page`, `feature_key`, `content`, `created_at`
- owner 与 role 必须一致，查询始终带 owner 范围。

### `medicine_inventory`

- `id`, `medicine_name`, `specification`, `quantity`, `unit`, `batch_no_masked`
- `expires_on`, `stock_status`, `source_updated_at`, `updated_at`
- `stock_status ∈ in_stock|low_stock|out_of_stock|expired|unknown`
- v1 只读查询；正式库无数据时返回空列表和 `source_status = empty`，不得生成假库存。

## 10. 数据保留与敏感字段

- session、限流和幂等记录按配置过期清理；撤销 session 保留最小审计期。
- Agent 输入/输出只保存业务所需最小文本；危机事件、访问审计和普通对话分表/分权限处理。
- `arguments_json` 和 `input_json` 写入前删除密码、身份证、手机号、邮箱、Cookie、CSRF、API Key 和完整病历正文。
- 所有 SQLite 外键保持开启；时间和状态由 Service 统一写入；迁移必须可在副本演练并通过 `foreign_key_check`、`integrity_check`。

## 11. 阶段 2 验收结论

- HTTP、Cookie/CSRF、统一响应、错误码、分页、幂等与 SSE 契约已冻结。
- 现有登录、注册、目录、患者助手和预约 DTO 已映射为 HTTP 结构。
- 医生/助理工具白名单、Agent 状态、事件和 v9 逻辑实体已明确。
- 契约不包含通用知识库/RAG，避免扩大 v1.0.0 范围。
- 可以进入阶段 3 的仓库与开发环境核验；实现若需改字段，必须先更新本文件。
