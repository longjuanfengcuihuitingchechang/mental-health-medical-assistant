# 助理端前端生成 Prompt

将下面整段内容直接粘贴给前端生成工具：

---

请在现有项目 `D:\SCY个人代码\assistant\fronts` 中新增完整的心理健康智能医疗助手“助理端”静态前端。必须复用现有 HTML + Tailwind CSS + 原生 JavaScript 技术栈和视觉语言，不引入 React、Vue、新包管理器或第三方 CDN。不要修改患者、医生和管理员的业务权限。

## 产品定位

助理负责患者、医生与系统预约流程的协调，处理超额预约提醒、医生公开工作安排、夜班排班缺口和只读库存查询。助理不是医生，不能诊断、处方、修改病历、查看量表答案或替医生决定是否接诊。

## 文件结构

创建：

```text
fronts/assistant/
├── index.html
├── appointments.html
├── doctor-schedules.html
├── night-shifts.html
├── inventory.html
└── profile.html
```

复用或抽取 `fronts/assets/css/app.css`、`fronts/assets/js/api.js`、`auth.js`、`ui.js`、`assistant-panel.js`。如果共享 assets 尚不存在，只创建清晰的待实现引用和模块设计，不复制六份内联业务逻辑。

## 统一布局和视觉

- 桌面端使用三栏布局：左侧 232px 深青灰导航，中间自适应工作区，右侧 340px 常驻“助理工作助手”。
- 主色使用 teal/青绿色，背景为温和浅灰，卡片白色、圆角 12px、轻阴影。危险红色只用于真实紧急状态。
- 768px 以下左侧导航与右侧助手均变为抽屉；360px 下不得横向溢出。
- 所有图标按钮有 `aria-label`，状态变化使用 `aria-live`，模态框支持焦点锁定、Esc 和焦点归还。
- 页面顶部显示当前助理姓名、角色、通知入口和退出登录。

## 左侧导航

导航项：协调工作台、预约升级、医生安排、夜班排班、药物库存、个人中心。当前项有明确文字和视觉选中状态，不只依赖颜色。

## 页面一：`assistant/index.html`

创建协调工作台：

- 统计卡：待医生确认超额预约、待患者选择、未来两天夜班缺口、休假医生、库存预警。每张卡标记更新时间。
- 主列表“需要协调”：患者显示名、医生显示名、预约日期、队列位置、当前状态、等待时长和“查看”按钮。
- “今日与未来两天”区域：夜班医生、医生容量和预约人数。
- 数据库或接口不可用时显示维护卡，不使用假成功数据。

## 页面二：`assistant/appointments.html`

- 筛选：状态、日期、医生、患者关键词；默认只显示活动协调项。
- 表格/移动卡片字段：预约编号缩写、患者显示名、医生、日期、容量、预约人数、队列位置、患者决定、医生决定、更新时间。
- 助理只能查看和追加普通协调备注；不能替患者选择、替医生接受/拒绝或修改状态机。
- 点击详情打开时间线抽屉，展示 `appointment_events`，历史不可编辑删除。
- 对应目标接口：`GET /api/v1/assistant/appointments/pending-decisions`。接口未接入时显示“预约协调接口待接入”。

## 页面三：`assistant/doctor-schedules.html`

- 展示未来两天医生卡：姓名、科室、职称、工作中/休假/不在岗/待确认、预计返岗、计划容量、预约人数、夜班标记。
- 支持按日期、科室、状态筛选。
- 状态缺失必须显示“待确认”，不能根据“在职”推断“正在接诊”。
- 只读页面，不允许助理修改医生接诊容量或工作状态。

## 页面四：`assistant/night-shifts.html`

- 使用未来 7 天日历/列表，每天只能有一个夜班医生。
- 未排班显示明显但不危险的“待安排”状态；已排班显示医生、科室、安排人和时间。
- 安排操作选择日期和医生，提交前二次确认。
- 对接 `POST /api/v1/night-shifts`；409 时提示“该日期已由其他人完成排班”，刷新真实数据，禁止覆盖。
- 不自动轮换、不随机选择、不用 LLM 决定值班医生。

## 页面五：`assistant/inventory.html`

- 提供药品名称关键词、库存状态、有效期范围筛选。
- 只展示名称、规格、库存数量、单位、批次有效期、库存状态、最后更新时间和来源系统。
- 禁止显示剂量建议、适应症推断、替代药推荐、处方入口或“一键补药”。
- 当前项目没有库存数据库/API，默认显示“药物库存接口待接入”，不得写入静态假库存；仅在显式 mock 模式展示并持续标记“演示数据”。

## 页面六：`assistant/profile.html`

- 显示助理账号、显示名、员工号、在职状态和通知偏好。
- 联系方式只显示掩码；不显示密码、完整身份证或内部 token。
- 提供退出登录；退出后清除内存状态和 `sessionStorage` 中的助手会话 ID。

## 右侧“助理工作助手”

每页始终存在，标题下显示：“用于协调查询和页面说明，不替代医生决定。”

进入页面或打开功能时调用目标接口：

```json
POST /api/v1/assistant/work-assistant/respond
{
  "page": "appointments",
  "feature_key": "pending_requests",
  "event": "page_open",
  "session_id": null,
  "message": ""
}
```

普通问答使用 `event="message"`。助手只能调用以下只读工具：

- `get_coordination_queue`
- `get_doctor_public_schedule`
- `get_night_shift_gaps`
- `get_appointment_counts`
- `get_patient_coordination_summary`
- `search_medicine_inventory`

任何写操作请求都回答“请在对应业务页面确认操作”，并提供白名单页面导航按钮。浏览器不得读取 `.env`、不得包含 DeepSeek API Key、不得直接请求 DeepSeek。

介绍规则：同一助理、页面、功能前 8 次展示后端模板，第 9 次收到 `introduction_suppressed` 后静默，不显示空气泡或 toast。跨页使用同一 `session_id`，通过历史接口恢复消息；401、退出或切换账号时清除。

## 状态与错误

- loading：骨架屏，不显示旧用户数据。
- empty：说明没有待协调项目，不使用庆祝性医疗结论。
- 403：显示无权限并隐藏已返回的敏感内容。
- 409：刷新预约或夜班真实状态。
- 423：显示 E 盘数据库不可用，禁用写操作。
- 503：工作助手降级，业务查询和现实安全信息保持可访问。
- offline：保留未提交的普通筛选条件，不缓存患者敏感正文。

## 禁止事项

- 不把助理设计成管理员或医生。
- 不让 LLM接受/拒绝预约、安排夜班、修改容量或查看病历正文。
- 不在前端计算患者是否完成 10 次就诊。
- 不使用真实患者姓名、手机号、证件号或心理记录作为静态数据。
- 不在没有回执时显示“已通知医生”“患者已收到”。
- 不把 mock、静态库存或浏览器本地状态展示为真实数据库结果。

## 验收

1. 六个页面导航完整，无死链。
2. 桌面、平板、手机布局和键盘操作通过。
3. 助理只能看预约协调最小信息，越权响应为 403。
4. 同日第二次夜班安排正确处理 409。
5. 工作助手跨页保留会话，第 9 次不再自动介绍。
6. 库存接口未接入时无假数据。
7. 与患者、医生同时登录时 Cookie、助手历史和预约状态不串号。
8. 控制台无未处理异常，所有请求具有 loading、empty 和 error 状态。

完成后输出：新增/修改文件清单、页面到接口映射、仍待后端实现的接口、mock 开关、响应式检查结果和未解决风险。不要执行安装、部署、Git 提交或推送。
