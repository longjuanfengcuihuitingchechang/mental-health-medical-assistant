# v1.0.0 测试策略与覆盖矩阵

## 1. 数据边界

- 默认测试只使用 `TemporaryDirectory` 内的 SQLite 数据库和明显虚构账号。
- 不读取 `.env`、`private/`、E 盘凭据导出或真实病历正文，不在测试输出中打印 Cookie、CSRF、Key、pepper 或密码。
- E 盘冒烟测试必须单独执行：先确认备份，只使用既有合成账号，禁止新增或修改真实医疗记录。
- E 盘缺失时明确跳过正式库验证，禁止回退到 C/D 盘创建替代正式库。

## 3. 本地统一入口

```powershell
Set-Location -LiteralPath 'D:\SCY个人代码\assistant'
.\scripts\Run-Tests.ps1
```

入口依次执行 Python 编译检查、全量测试、全部前端 JavaScript 语法检查、Git 敏感文件跟踪检查、差异空白检查，并在 Docker 可用时验证 Compose 配置。它不会执行容器构建、修改 `.env` 或访问 E 盘正式库。

## 4. E 盘正式库冒烟边界

允许：数据库存在性、schema 版本、`PRAGMA integrity_check`、合成账号只读登录与角色页面读取。

禁止：创建真实患者、修改病历/处方/诊疗对话、重置正式账号密码、运行会调用外部模型并发送正式数据的用例。

## 5. CI/CD 目标门禁

GitHub Actions 目标流程为：Python 测试 → 敏感文件和值检查 → JavaScript/迁移验证 → 容器构建 → 人工发布门禁。Workflow 只使用合成临时数据库，不接触 E 盘；发布作业不得由普通分支或 Pull Request 自动触发。

在用户单独明确授权修改 CI/CD 前，本节仅作为契约，不创建 `.github/workflows`。
