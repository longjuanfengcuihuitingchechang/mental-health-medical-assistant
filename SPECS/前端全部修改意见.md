# 心理健康智能医疗助手：前端全部修改意见

## 1. 实施范围与现状

现有 `fronts` 为 HTML + Tailwind CSS + 原生 JavaScript 静态页面，共 15 个页面。保留现有视觉基础，但把综合医疗内容收敛为心理健康筛查、情绪支持、正式诊疗、预约协同、风险复核和随访。

本文件是前端实施清单，不代表所有 HTTP API 已存在。页面必须区分：真实接口、显式 mock、待接入。禁止把 mock 成功伪装成真实医疗操作。

## 2. 全局技术与安全要求

- API 前缀集中配置为 `/api/v1`，统一 `fetch`、超时、错误映射、`X-Request-ID` 和 `credentials: "include"`。
- 不在浏览器保存密码、Cookie、token、API Key、病历正文或量表答案；DeepSeek 只能由后端调用。
- `sessionStorage` 只允许保存非授权性质的助手会话 ID；401、退出或切换账号时清除。
- 所有页面覆盖 loading、empty、offline、403、409、423、429、503。
- 写操作防重复提交并支持幂等键；409 时重新加载真实状态。
- 360px、768px、1440px 下无关键内容遮挡；模态框支持焦点锁定、Esc 和焦点归还。
- 医疗风险、医生状态、库存、排队和预约结果只能展示服务端数据。

## 3. 公共布局

- 桌面端：左侧角色导航、中间业务区、右侧角色助手。
- 768px 以下：左侧导航变抽屉，助手变右侧抽屉。
- 360px：助手使用固定悬浮按钮打开，不遮挡危机卡和提交按钮。
- 公共组件：`LoadingSkeleton`、`EmptyState`、`ErrorState`、`PermissionState`、`OfflineBanner`、`StatusBadge`、`QueueBadge`、`CrisisSupportCard`、`AssistantPanel`。
- 助手标题下始终显示角色边界，例如“用于工作查询与页面说明，不替代医疗判断”。

## 4. 登录与注册

### `fronts/index.html`

- 身份选项增加患者、医生、助理、管理员。
- 对接 `POST /auth/login`，再通过 `/auth/session` 校验服务端角色后跳转。
- 跳转路径：患者 `patient/index.html`、医生 `doctor/index.html`、助理 `assistant/index.html`、管理员 `admin/index.html`。
- 连续第 7 次失败显示“再失败一次将锁定”；第 8 次显示锁定 5 分钟和剩余秒数。
- 不提示账号是否存在，不再按下拉框直接模拟登录。

### `fronts/register.html`

- 患者注册后可登录；医生显示“等待管理员审批”。
- 助理不开放公开注册，只能由受控初始化或管理员流程创建。
- 分离用户协议、隐私政策和 AI 助手同意；AI 同意不得成为普通注册的强制条件。

## 5. 患者端

导航：心理健康概览、智能支持、心理测评、情绪日记、患者诊疗、随访与资源、个人与隐私。

### 改造现有页面

- `patient/index.html`：情绪打卡、最近筛查、趋势、随访和现实求助入口。
- `patient/online-consultation.html`：智能支持对话，不冒充医生；危机命中固定显示 12356、110、120。
- `patient/vital-signs-checkin.html`：改为情绪日记，记录情绪、压力、睡眠和可选备注。

### 新增页面

- `patient/assessments.html`：量表列表、继续测评、历史结果和非诊断声明。
- `patient/resources.html`：随访、专业资源、隐私和 AI 同意。
- `patient/care.html`：医生选择、原接诊医生、状态、休假、排队和提前预约。

### 提前预约

- 仅展示服务端返回的已完成就诊次数；达到 10 次才启用指定医生。
- 展示医生未来两天容量、预约人数、本人队列位置和夜班信息。
- 超额时先询问换医生或坚持；坚持后显示“等待医生确认”，不得显示预约成功。
- 医生接受后仍显示队列；拒绝时展示服务端直接/委婉文案。

### 患者助手

- 页面或功能打开时发送 `page_open/feature_open`；前 8 次显示模板介绍，第 9 次静默停止。
- 跨页携带 `assistantSessionId`，进入新页后恢复历史消息。
- 只回答当前页面功能；正式诊疗意图跳转 `patient/care.html`。
- 不在前端计算年龄，使用服务端 `age_group` 控制表达和可访问性。

## 6. 医生端

导航：工作台、我的患者、在线支持、预约与容量、风险事件、随访管理、药物库存、个人中心。

### 页面改造

- `doctor/index.html`：高风险待确认、今日随访、未读对话、超额预约弹窗、未来两天容量、今日夜班。
- `doctor/my-patients.html`：仅展示负责患者；操作改为心理档案、随访、量表、对话。
- `doctor/online-consultation.html`：患者授权、风险徽标、筛查摘要、真实人工消息与 AI 建议明确区分。
- `doctor/schedule-appointments.html`：改为“预约与容量”，设置未来两天接诊人数，查看队列和超额请求。
- `doctor/prescriptions-records.html`：改为 `doctor/risk-events.html`，保留追加式处置记录，关闭必须填写理由。
- `doctor/profile.html`：专业资料、通知偏好和工作状态。

### 新增 `doctor/inventory.html`

- 只读查询药品名称、规格、库存数量、单位、库存状态、批次有效期和最后更新时间。
- 禁止提供剂量、适应症推断、替代药、开药按钮或处方建议。
- 当前无库存数据源时显示“库存接口待接入”，不得展示伪造数字。

### 医生工作助手

右侧常驻，允许调用：

- `get_my_schedule`：本人排班、预约、随访和夜班。
- `get_my_capacity`：未来两天容量与已预约人数。
- `get_pending_overcapacity_requests`：本人待确认超额预约。
- `search_my_patient_visible_summary`：仅本人负责患者的最小可见摘要。
- `search_medicine_inventory`：只读库存摘要。

助手不得接受/拒绝预约、关闭风险事件、修改病历、生成诊断/处方或替医生发消息。写操作必须由医生点击业务按钮完成。

## 7. 助理端

新增目录与页面：

```text
fronts/assistant/
├── index.html
├── appointments.html
├── doctor-schedules.html
├── night-shifts.html
├── inventory.html
└── profile.html
```

- `index.html`：协调概览、超额预约、夜班缺口、医生状态、库存预警摘要。
- `appointments.html`：患者坚持后的协调队列，只显示预约必要信息。
- `doctor-schedules.html`：医生公开工作状态、未来两天容量和预约人数。
- `night-shifts.html`：安排每日唯一夜班医生，409 时刷新而非覆盖。
- `inventory.html`：药物库存只读查询；数据源未接入时明确显示不可用。
- `profile.html`：助理基本资料、通知偏好、退出登录。

助理不能查看患者病历正文、量表答案、诊断、私密对话、身份证或完整联系方式，不能替医生接受预约。

### 助理工作助手

允许调用：

- `get_coordination_queue`：待患者/医生处理的预约元数据。
- `get_doctor_public_schedule`：医生公开工作状态、容量、预约数、休假和夜班。
- `get_night_shift_gaps`：未安排夜班的日期。
- `get_appointment_counts`：按医生和日期汇总人数。
- `get_patient_coordination_summary`：仅预约协调所需的患者显示名、队列和状态。
- `search_medicine_inventory`：只读库存摘要。

所有工具只读。助手可以导航到业务页面，但不能代替助理提交排班或修改预约状态。

## 8. 管理员端

导航：系统概览、患者管理、专业人员管理、助理管理、注册申请、量表与资源、安全审计、数据与备份。

- `admin/index.html`：账号、风险、数据库、备份和夜班缺口。
- `admin/patients.html`：患者账号状态、黑名单和最小基本信息。
- `admin/doctors.html`：医生在职状态、工作状态和注册审批。
- 新增 `admin/assistants.html`：助理账号、在职状态和黑名单，不展示密码。
- `admin/registration-requests.html`：医生审批，批量操作逐条反馈。
- `admin/data-import.html`：改为数据与备份，显示 E 盘健康、WAL、完整性和恢复状态。
- 新增 `admin/audit.html`、`admin/assessment-resources.html`。

## 9. 角色助手统一请求

目标接口：

```json
POST /api/v1/{role}/work-assistant/respond
{
  "page": "appointments",
  "feature_key": "pending_requests",
  "event": "message",
  "session_id": "uuid",
  "message": "明天有哪些超额预约？"
}
```

响应类型：`page_intro`、`page_answer`、`tool_result`、`navigation`、`out_of_scope`、`introduction_suppressed`、`crisis_support`、`error`。工具结果必须显示数据更新时间和来源；状态未知时写“待确认”。

## 10. 接口未实现时的处理

- 当前已实现领域 Agent：登录、注册、医生审批、管理员目录、患者页面助手、预约容量、预约状态机、夜班和助理账号。
- 当前尚未接入 HTTP 路由，因此前端不得声称这些 URL 已经可用。
- 医生/助理工作助手工具路由、药物库存表及库存 API 尚未实现，页面必须显示“待接入”。
- Mock 模式只能用于视觉演示，并在页面顶部持续显示“演示数据，未写入医疗记录”。

## 11. 多账号验收

- 使用不同浏览器 Profile/无痕窗口同时登录 2 位患者、1 位医生、1 位助理和可选管理员。
- 验证超额预约从患者坚持、医生弹窗、医生决定到助理队列状态完全一致。
- 验证医生助手不能查询其他医生患者，助理助手不能读取病历正文。
- 验证退出/401 后 Cookie、助手会话和页面缓存不串号。
- 验证库存接口不可用时不显示静态假库存。
