# 心理健康专项智能医疗助手：产品需求文档

| 项目 | 内容 |
|---|---|
| 文档版本 | 1.0 |
| 日期 | 2026-08-06 |
| 产品阶段 | MVP 规划 |


## 1. 产品定位

面向患者、心理/精神卫生专业人员和管理员的心理健康管理与支持系统。系统提供心理筛查、情绪与睡眠记录、智能对话、专业人员复核、随访和危机转介协同；它是健康教育与临床工作辅助工具，不替代医生，不给出医学确诊，不自动开具处方或治疗方案。

现有代码已具备管理员、医生、患者三角色，SAS/SDS/SCL-90 测评、诊断报告、AI 聊天授权、日常检查和对话记录等基础能力；指定 Tailwind 前端包含 15 个静态 HTML 页面，但尚未接入 HTTP API。

## 2. 产品目标

- 将现有分散的心理测评、对话、报告和授权能力整合为可审计的心理健康专项助手。
- 让患者完成筛查后获得清晰、克制、可行动的支持信息，并能联系专业人员。
- 让医生查看结构化风险摘要、量表趋势、对话风险事件和随访任务，但始终由医生做最终判断。
- 让管理员管理账号、量表版本、危机资源、审计事件和数据备份状态。
- 将业务数据库固定部署到 E 盘明确目录，移动硬盘缺失时禁止静默写入系统盘。

## 3. 用户与权限

| 角色 | 主要诉求 | 权限边界 |
|---|---|---|
| 患者 | 自助筛查、情绪记录、获得支持、联系医生 | 仅访问本人数据；不能看到内部风险规则和他人信息 |
| 医生/心理专业人员 | 查看负责患者、复核风险、发起随访、记录处置 | 仅访问授权或分配患者；高风险处置需留痕 |
| 管理员 | 账号、配置、审计与数据运维 | 默认不查看对话正文；敏感查看需理由和审计 |
| 系统服务 | 量表计分、风险规则、模型编排、通知 | 最小权限；不得绕过人工复核或直接改变诊断 |

## 4. MVP 范围

### 4.1 患者端

1. 登录、退出、查看与维护个人基本资料。
2. 查看可用量表，完成版本化问卷，提交后查看筛查结果与解释。
3. 记录每日情绪、睡眠、压力及可选备注，查看近 7/30 天趋势。
4. 与智能助手进行文本对话；对话开始前展示非诊断声明和隐私提示。
5. 查看专业资源、本人风险提示和随访安排。
6. 出现危机信号时，立即显示求助卡：`12356`、当地急救/报警渠道及联系可信任人员；不得只返回普通聊天文本。

### 4.2 医生端

1. 查看负责患者列表、最近筛查结果、趋势和待处理风险事件。
2. 查看量表原始答案、确定性得分、规则命中原因和历史版本。
3. 对风险事件执行确认、联系中、已转介、误报、已关闭等处置并填写备注。
4. 创建随访任务、发送量表、记录会诊/随访摘要。
5. 查看经过授权的对话记录；系统记录访问者、时间、理由和范围。

### 4.3 管理端

1. 管理患者、医生、注册申请、角色与启用状态。
2. 管理量表定义及版本；已产生答卷的版本不可覆盖，只能停用并新建版本。
3. 配置危机帮助资源、值班联系人和模型策略。
4. 查看审计日志、数据库状态、备份状态和失败告警。

### 4.4 智能助手

- 支持情绪支持、心理健康教育、量表引导、趋势解释、就医/求助导航。
- 只使用完成当前回复所需的最小上下文。
- 高风险识别采用“确定性规则优先 + 模型辅助召回 + 人工复核”；模型不得降低规则判定的风险级别。
- 生成内容不得冒充专业人员，不得给出处方、剂量调整、确诊或保证性结论。

## 5. 核心用户流程

### 5.1 普通支持流程

```text
登录 -> 同意隐私与助手边界 -> 对话/记录情绪
     -> 规则与模型安全检查 -> 支持性回复
     -> 推荐量表、科普或预约 -> 保存最少必要记录
```

### 5.2 量表流程

```text
选择量表版本 -> 获取题目 -> 本地暂存答题进度
-> 服务端校验完整性 -> 确定性计分 -> 风险规则
-> 展示筛查解释 -> 必要时创建风险事件 -> 医生复核
```

### 5.3 危机流程

```text
用户文本/量表答案触发高风险
-> 立即返回危机支持卡与现实世界求助选项
-> 创建高优先级风险事件并记录命中依据
-> 通知已配置的专业人员（需合法授权与可用通道）
-> 人工确认、联系、转介、关闭，全程审计
```

系统不得宣称已经联系急救人员，除非外部通道返回可验证的成功回执。

## 6. 功能需求

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---:|---|
| FR-01 | 三角色认证与基于角色的授权 | P0 | 越权请求统一返回 403 并写安全审计 |
| FR-02 | 患者档案与医生分配 | P0 | 患者只能访问本人，医生只能访问负责患者 |
| FR-03 | 量表定义、版本、答卷与确定性计分 | P0 | 相同答案和版本重复计算结果一致 |
| FR-04 | 情绪/睡眠/压力日记与趋势 | P0 | 支持日期筛选，重复日期按业务规则处理 |
| FR-05 | 智能对话与流式回复 | P0 | 可中断；错误不产生虚假完成状态 |
| FR-06 | 危机识别与处置工作流 | P0 | 高风险响应不依赖大模型成功 |
| FR-07 | 医生复核、备注与随访 | P0 | 每次状态变化包含操作者、时间和原因 |
| FR-08 | 危机资源和量表版本管理 | P1 | 发布前校验；历史引用保持不变 |
| FR-09 | 审计查询与数据导出 | P1 | 敏感导出需权限、理由、水印/记录 |
| FR-10 | 数据备份、恢复演练和磁盘状态 | P0 | E 盘不可用时只读或拒绝启动，不回退系统盘 |

## 7. 前端复用要求

保留指定前端的登录/注册、三角色导航、管理员管理、医生工作台/患者/排班/问诊、患者首页/问诊/体征打卡页面和 Tailwind 视觉语言。专项化调整在后续前端提示词中完成，本阶段不修改 HTML。

需要新增或重构的页面能力：心理量表中心、情绪日记、风险事件队列、筛查详情、随访管理、危机资源配置、隐私授权与审计查看。现有“处方与病历”不属于患者自助助手核心，MVP 仅保留医生记录入口，不让 AI 生成处方。

## 8. 非功能需求

- 安全：医疗健康信息按敏感个人信息处理；单独同意、最小必要、访问审计和撤回机制必须可验证。
- 可用性：本地 API 健康检查成功率目标 99.5%；高风险规则引擎不依赖外部模型。
- 性能：普通列表 P95 小于 500 ms；首个流式文本事件目标小于 2 s（不含外部模型拥塞）。
- 可恢复性：数据库 RPO 不超过 24 h，RTO 不超过 4 h；每季度至少一次恢复演练。
- 可访问性：关键操作支持键盘、可见焦点、语义标签和足够对比度。
- 可追溯性：量表、风险规则、模型、提示词和同意文本均记录版本。

## 9. 明确不做

- 自动诊断精神障碍、自动分诊替代专业人员、自动处方或调整药物。
- 仅凭单次量表或模型输出决定住院、强制干预或其他重大医疗决定。
- 未配置真实通道时自动联系亲友、医生、警方或急救。
- MVP 中的音视频问诊、可穿戴设备实时采集、跨机构数据互联。
- 把 E 盘移动硬盘当作多人并发或生产级数据库服务器。

## 10. 成功指标

- 量表完整提交成功率 ≥ 99%。
- 高风险规则触发后危机支持卡展示率 = 100%。
- 高风险事件均具有人工处置状态和完整审计记录。
- 越权访问自动化测试通过率 = 100%。
- 数据库恢复演练成功，且无静默写入系统盘事件。

## 11. 待确认事项

1. MVP 是单机研究原型，还是需要局域网多用户并发；后者不应采用 E 盘 SQLite 作为生产方案。
2. 已确认目标用户包括未成年人和老年人；当前已加入年龄分层、监护支持状态和统一危机流程，具体监护授权文本仍需法务与医院确认。
3. 采用哪些正式授权的量表版本、题目文本、计分规则和临床阈值。
4. 医生值班通知渠道及其授权范围。
5. 外部模型供应商、数据驻留地区、是否允许敏感数据出境。

## 13. 患者端常驻页面助手需求

- 患者端每个功能页右侧常驻同一个助手面板；进入页面后自动显示一次简短功能说明。
- 助手仅回答当前页的功能和操作问题。识别到其他页面主题时给出跳转建议，不在原页面扩展回答。
- 用户表达正式诊疗意图时进入独立“患者诊疗”页，并展示可选择医生。
- 原接诊医生优先展示，同时呈现真实在岗、休假、预计返岗、队列人数和本人队列位置；缺失数据明确写“待确认”。
- 年龄由出生日期计算。未成年人使用发展阶段适宜、非命令式语言，并提示监护支持；老年用户使用清晰、尊重、不催促的表达。
- 页面助手不是医生，不作诊断、处方或重大医疗决定，也不声称已经完成现实通知。

验收指标：页面进入说明命中率 100%；跨页问题不调用普通问答模型；医生状态与数据库一致；危机提示不依赖模型；患者越权和非患者调用测试全部失败。

## 14. 提前预约与助理协同

- 累计完成就诊达到 10 次后，患者可指定医生预约未来两天，并看到该医生当日预约人数和自己的队列位置。
- 医生每天设置未来第 1、2 天容量。超额预约先由患者选择换医生或坚持；坚持后进入医生待确认弹窗。
- 医生接受后患者仍按队列等待；拒绝时选择直接通知或委婉通知。
- 每日最多一位夜班医生；缺失排班必须显示缺口，不能自动编造医生。
- 新增 2 个合成助理账号，助理负责预约升级和夜班协调，但不能替医生作临床决定。
